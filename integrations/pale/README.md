# Pale integration

This planned package publishes Weave's committed, secret-free occurrences to Pale and tracks delivery and recovery under the [occurrence contract](../../contracts/pale-occurrences.md). It chooses no agent, model, tool or machine. Pale's acquisition, query and command caller lives in Pale's own repository; each product uses the other's public contracts and records its own outcomes. Both products must run independently.

Weave reaches Scope, Counsel and Reckon only through Pale when that integration is selected, for the requests Weave's own work makes. Scope reads Weave through Weave's read port, still to be proposed by Scope's and Weave's builders, with Pale or without it, and without Pale it is how an agent reads Weave; Weave itself never calls Scope. Weave contains no built-in model catalogue, model or automatic outbound message. Scope, reading Weave without Pale, may use Counsel's memory host on Scope's side; Weave still calls no model. Direct, permitted reads of exact work, goal, relationship, decision and evidence records can hydrate context without Scope, with required blockers, omissions and budgets explicit.

A source helper reading for a selected Scope request retains the Weave credentials. It returns a revision-bound, secret-free result containing owner and permission reference, source instance and record, revision, observation time, freshness, purpose, model-use limit, revocation coordinates and conflict owner. It returns no credential, credential reference or runtime binding to Scope. Scope separately admits, deduplicates and checks freshness for its own projection; this never becomes a direct Weave-to-Scope connector.

Pale's input acquisition separates request/selection, Weave snapshot/read result, Pale capture, compilation, activation and use. Captured values cannot become “latest” lookups during evaluation or silent stale fallbacks. A result flowing back cannot rewrite the same generation's input; it belongs to a later capture. The caller owns these stages, while Weave owns its local read and command checks.

Each relation exported to Pale must name its one destination graph and edge class. Labels such as owns, parent, inside, reports-to, member, agent or belongs-to cannot be admitted as an unresolved hierarchy. Preserve Weave's edge identities and revisions and distinguish witnessed routes from direct edges. Pale owns the destination graph definitions and their acceptance. A relation read by Pale [creates no principal, delegation or permission there](../../contracts/pale-occurrences.md#what-weave-checks-on-a-pale-controlled-command).

The [acceptance plan](../../tests/pale/README.md) covers Weave's half of the seam. Publication of versioned schemas and Pale's consumer pin precede a claim of live interoperability. Reusing neutral source libraries creates no runtime connection or shared lifecycle.
